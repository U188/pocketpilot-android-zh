# Промпт: Android-приложение для работы с OpenCode и файлами

## Роль

Ты — senior Android-разработчик (Kotlin, Jetpack Compose) и архитектор. Твоя задача — спроектировать и написать полностью рабочее Android-приложение, которое даёт мобильный интерфейс к OpenCode (AI-агент для кодинга) и удобную работу с файлами сервера, «как на компьютере».

## Контекст

- Пользователь работает только с телефона.
- OpenCode запущен на удалённом сервере (VPS, Linux) в режиме сервера (`opencode serve`).
- Приложение — клиент: оно **не** запускает OpenCode на телефоне, а подключается к серверу.
- Файлы лежат на сервере, доступ к ним — по SFTP/SSH.
- Приложение создаётся в Google AI Studio (Build → платформа Android). Все требования ниже должны укладываться в его ограничения: Kotlin + Jetpack Compose, один модуль, одна Activity, без Java/XML-разметки, без NDK и нативного кода, только клиентская часть (без своего серверного бэкенда).

## Цель

Одно приложение вместо связки «терминал + редактор + чат с ИИ»:

1. Чат с OpenCode-агентом (сессии, стриминг ответов, инструменты, разрешения).
2. Файловый менеджер сервера с редактором кода.
3. Встроенный терминал (SSH).

## Функциональные требования

### 1. Подключение к серверу

- Экран профилей серверов: имя, хост, порт SSH, порт OpenCode, логин.
- Авторизация SSH: пароль или приватный ключ (импорт из файла, генерация ключа в приложении).
- Секреты хранить в Android Keystore / EncryptedSharedPreferences.
- Проверка соединения, индикатор статуса, автопереподключение.
- Подключение к OpenCode HTTP API через SSH-туннель (port forwarding), чтобы порт OpenCode не торчал в интернет.

### 2. Чат с OpenCode

- Список сессий: создать, открыть, переименовать, удалить, форк.
- Отправка сообщений, стриминг ответа в реальном времени (SSE).
- Отображение: markdown, блоки кода с подсветкой и кнопкой «копировать», вызовы инструментов (чтение/правка файлов, команды) в сворачиваемых карточках.
- Показ диффов изменений файлов (добавлено/удалено).
- Запросы разрешений от агента (выполнить команду, изменить файл) — диалог «разрешить / разрешить всегда / отклонить».
- Выбор провайдера, модели и агента (build / plan).
- Прикрепление файлов из файлового менеджера к сообщению (упоминание через `@`).
- Кнопка остановки генерации, откат изменений.
- Актуальные эндпоинты и схему брать из OpenAPI-спецификации сервера OpenCode (обычно доступна по пути `/doc`), а не придумывать. Если что-то неясно — сначала явно перечисли допущения.

### 3. Файловый менеджер («как на компьютере»)

- Дерево папок и список файлов, хлебные крошки, сортировка, поиск по имени и по содержимому.
- Операции: создать файл/папку, переименовать, копировать, вырезать, вставить, удалить (с подтверждением), перемещение.
- Выделение нескольких файлов (долгий тап), контекстное меню.
- Загрузка файлов с телефона на сервер и скачивание на телефон (Storage Access Framework).
- Права доступа (chmod), размер, дата изменения, скрытые файлы.
- Фоновые операции с прогрессом и очередью передач.
- Планшетный/широкий режим: две панели (сервер ↔ телефон).

### 4. Редактор кода

- Подсветка синтаксиса (основные языки: Python, JS/TS, Kotlin, JSON, YAML, Markdown, Bash, HTML/CSS).
- Нумерация строк, поиск и замена, отмена/повтор, перенос строк, масштаб шрифта.
- Панель спецсимволов над клавиатурой (`{ } [ ] ( ) < > ; : " ' / \ | Tab`).
- Сохранение на сервер, индикатор несохранённых изменений, защита от конфликтов (если файл изменился на сервере).
- Открытие файла, который изменил агент, с обновлением в реальном времени.

### 5. Терминал

- SSH-терминал с поддержкой цветов (ANSI), вкладок и панели Ctrl / Alt / Esc / Tab / стрелки.
- Быстрые команды (сниппеты): список, который можно редактировать.
- Длинные тексты вставляются порциями, чтобы не обрезались.

## Нефункциональные требования

- Kotlin, Jetpack Compose, Material 3, тёмная и светлая темы.
- Архитектура: одна Activity, один Gradle-модуль, MVVM (ViewModel + StateFlow), пакеты `data / domain / ui` внутри модуля.
- Coroutines + Flow, Room (локальный кэш и профили). DI — вручную (простой контейнер зависимостей), Hilt только если он поддерживается в проекте.
- Сеть: Ktor Client или Retrofit/OkHttp (+ SSE), SSH/SFTP — SSHJ или Apache MINA SSHD. Только чистые JVM-библиотеки из Maven/Google, без нативного кода. Секреты не требуют Firebase: хранить локально (Keystore).
- minSdk 26, targetSdk — актуальный.
- Приложение не должно падать при потере сети; все операции отменяемые.
- Работа сервиса соединения в фоне (foreground service) с уведомлением, чтобы сессия не рвалась при сворачивании.
- Без телеметрии и сторонней аналитики. Весь трафик — только к серверу пользователя.
- Русский интерфейс по умолчанию, строки в `strings.xml` для локализации.

## Безопасность

- Проверка host key сервера (known_hosts, предупреждение при смене).
- Секреты не логируются и не попадают в бэкап (`allowBackup=false` для секретов).
- Биометрическая блокировка приложения (опционально).
- Явное подтверждение опасных действий (удаление, `rm -rf`, перезапись).

## Экраны

1. Список серверов → добавление/редактирование.
2. Главный экран с нижней навигацией: **Чат**, **Файлы**, **Терминал**, **Настройки**.
3. Чат: список сессий → экран сессии.
4. Файлы: дерево → редактор.
5. Настройки: тема, шрифт редактора, модели по умолчанию, сниппеты, безопасность.
